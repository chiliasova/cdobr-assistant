# Помощник по Инструкции ДОУ (кейс ЦДОБР)

Прототип чат-бота, который помогает сотруднику работать с Инструкцией по документообороту:
находит нужный пункт, объясняет простым языком со ссылкой, честно говорит, когда ответа нет,
готовит черновик приказа или распоряжения по модульному документу и считает маршрут визирования.

Всё работает локально: open source LLM через [Ollama](https://ollama.com), никаких внешних API.

## Быстрый старт (Windows)

1. Установите Ollama и модели (один раз):
   ```
   ollama pull qwen3:4b-instruct-2507-q4_K_M
   ollama pull bge-m3
   ```
2. Установите Python 3.13 (стабильный, не бета) с https://www.python.org/downloads/ (галочка «Add python.exe to PATH»).
3. Скачайте проект и запустите `run.bat` двойным щелчком.
4. Откройте http://127.0.0.1:8000. Демо-входы: `employee / employee` (сотрудник), `doc / doc` (Департамент ДОУ, видит журнал и переиндексацию).

Демо встраивания в портал: http://127.0.0.1:8000/static/portal-demo.html (кнопка «?» справа внизу).

## Что умеет

| Функция | Где в коде |
|---|---|
| Ответы по Инструкции со ссылками на пункты и % релевантности | `app/answer.py`, `app/search.py` |
| Отказ, если ответа в базе нет (порог релевантности + ответ модели «НЕТ ОТВЕТА») | `app/answer.py` |
| Проверка ответа: каждая ссылка и каждое число должны быть в найденных пунктах | `answer.verify` |
| Черновик по модулю: поля из сносок шаблона, заполнение по описанию, чистка по п. 3.3 методички | `app/modules.py` |
| Маршрут визирования по Матрице с уточняющими вопросами | `app/routing.py` |
| Проверка загруженного проекта .docx | `modules.check_draft` |
| Вход, роли «сотрудник» и «Департамент ДОУ», журнал вопросов и оценок | `app/main.py` |
| Поп-ап виджет для портала | `static/widget.js` |

## Как устроено

1. **База знаний** (`data/sources/`): Инструкция режется на пункты («10.3»), Матрица — на строки, методичка — на пункты, модули — на карточки. Хеш файлов — версия базы: заменили файл, индекс пересобрался.
2. **Поиск**: BM25 по леммам (pymorphy3) + векторы bge-m3, объединение через RRF. Без Ollama работает только BM25.
3. **Ответ**: модель qwen3:4b получает 5 найденных фрагментов и пересказывает их со ссылками. Если проверка не прошла, показываем дословный пункт.
4. **Модули**: поле — прочерк или вариант `[а / б]`, сноска `[N]` даёт подпись и пояснение. Модель раскладывает свободное описание по полям, пользователь проверяет, python-docx собирает файл.

## Настройки (переменные окружения)

`OLLAMA_URL` (по умолчанию `http://127.0.0.1:11434`), `LLM_MODEL`, `EMBED_MODEL`, `USE_LLM=0` (только цитаты), `USE_EMBEDDINGS=0` (только BM25), `MIN_RELEVANCE`, `TOP_K`, `CDOBR_SECRET`.

## Тесты

```
.venv\Scripts\python -m pytest -q
```
Тесты используют заглушку Ollama и не требуют моделей.

Документы в `data/sources/` — учебные материалы кейса, выданные организаторами хакатона.
